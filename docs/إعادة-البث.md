# وسيط إعادة البثّ — حلّ صوت AC3

## المشكلة

بثّ Xtream عندك يحمل صوت `ac3` (٦ قنوات). لا كروم ولا فايرفوكس يفكّ هذا
الترميز، فيُعرض الفيديو ويُسقَط الصوت بصمت. الفيديو `h264` مدعوم أصلاً —
فالمطلوب تحويل الصوت وحده.

## التثبيت

```bash
sudo bash /var/www/html/iptv/setup_restream.sh
```

يثبّت ffmpeg، ويهيّئ مجلد الذاكرة، ويضبط Apache لخدمة المقاطع، ويجدول
التنظيف، ويجري اختباراً ذاتياً. للتعطيل: `sudo bash setup_restream.sh --off`

---

## التصميم: عملية لكل قناة لا لكل مشاهد

هذه أهمّ نقطة. الطريقة الساذجة تشغّل ffmpeg لكل مشاهد — عند ٥٠٠ مشاهد
تعني ٥٠٠ عملية و٥٠٠ نسخة مسحوبة من المزوّد. مستحيل.

هنا عملية واحدة لكل **قناة** تكتب مقاطع HLS، ويقرأها كل مشاهدي تلك القناة
عبر Apache كملفات ساكنة:

```
مزوّد Xtream ──→ ffmpeg (واحد للقناة) ──→ /dev/shm ──→ Apache ──→ ٥٠٠ مشاهد
                  ينسخ الفيديو
                  يحوّل AC3←AAC
```

٥٠٠ مشاهد موزّعين على ٢٠ قناة = ٢٠ عملية = نواة واحدة تقريباً.

---

## الأرقام المقيسة

| البند | القيمة | كيف قيست |
|---|---|---|
| المعالج لكل قناة | **٥٪ من نواة** | قناة 720p بالزمن الحقيقي |
| الذاكرة لكل قناة | **~٥٥ ميغابايت** | عملية ffmpeg |
| المقاطع لكل قناة | **~١٫٥ ميغابايت** | ٦ مقاطع × ٤ ثوانٍ |
| زمن بدء القناة الباردة | **٢–٤ ثوانٍ** | حتى ظهور أول قائمة |
| ٢٥ قناة متزامنة | **~١٫٥ نواة · ٣٥ ميغابايت في الذاكرة** | حسابياً من أعلاه |

الفيديو يُنسخ بلا إعادة ترميز — ولهذا التكلفة منخفضة إلى هذا الحدّ.
تحويل الفيديو أيضاً كان سيكلّف ٥٠–١٠٠ ضعفاً.

## وضع الأفلام (VOD) — يُصلح MKV أيضاً

مكتبتك موزّعة على نوعين، ولكلٍّ معالجة مختلفة:

| | البثّ الحيّ (`channels`) | الأفلام والحلقات (`episodes`) |
|---|---|---|
| التخزين | `/dev/shm` (ذاكرة) | `storage/vod` (قرص) |
| القائمة | ٦ مقاطع متدحرجة | كل المقاطع تبقى |
| الإرجاع | لا معنى له | يعمل ✔ |
| المسار العام | `/hls` | `/vodhls` |
| مهلة الخمول | ٦٠ ثانية | ١٨٠ ثانية |

**لماذا الأفلام على القرص:** الفيلم يحتفظ بكل مقاطعه ليعمل شريط التقدّم.
ساعتان بمعدّل ٢ ميغابت = ١٫٨ غيغابايت — وذلك يملأ `/dev/shm` بفيلم واحد
ويُسقط الخادم.

**والوسيط يُصلح مشكلتين لا واحدة:** ترميز AC3 الذي لا يفكّه المتصفح،
و**حاوية MKV التي لا يفتحها أصلاً** — لأن الخرج HLS/TS في الحالتين.
نحو ٧٠٪ من مكتبتك ملفات `.mkv` لم تكن تعمل إطلاقاً، لا صورة ولا صوت.

**حصّة القرص** (`RESTREAM_VOD_QUOTA_MB`) تُضبط تلقائياً عند التهيئة إلى
ربع المساحة الحرة. عند بلوغها يُنظَّف المهجور أولاً، فإن بقيت ممتلئة
رُفض الطلب برسالة واضحة بدل ملء القرص — وامتلاء القرص لا يُعطّل الأفلام
وحدها بل يُسقط قاعدة البيانات وسجلّات Apache معها.

## ⚠ القيد الحقيقي: النطاق الترددي

المعالج ليس المشكلة. **النطاق هو المشكلة.**

اليوم مشاهدوك يسحبون من خادم Xtream مباشرةً فلا يمرّ شيء بخادمك. الوسيط
ينقل ذلك كلّه إليك:

| المشاهدون | الصادر المطلوب |
|---|---|
| ٥٠ | ~٢٥٠ ميغابت/ث |
| ٢٠٠ | ~١ غيغابت/ث |
| ٥٠٠ | **~٢٫٥ غيغابت/ث** |

بمعدّل ٥ ميغابت للمشاهد. راجع `capacity_check.php` ليقيس واجهتك الفعلية.
إن كانت ١ غيغابت فالحدّ العملي نحو ١٦٠ مشاهداً — ولا يحلّ ذلك معالجٌ أسرع.

**بديل بلا تكلفة:** اطلب من مزوّد Xtream مسار صوت AAC. كثير من اللوحات
توفّره، وحينها لا تحتاج الوسيط إطلاقاً.

## كيف يعمل تلقائياً

1. المشغّل يقرأ ترميز الصوت من قائمة HLS.
2. إن وجد مساراً صوتياً بديلاً مدعوماً في نفس البثّ → يتحوّل إليه فوراً.
3. وإلا يطلب `restream.php?ch=<id>`.
4. الخادم يشغّل ffmpeg للقناة (أو يعيد استخدام العملية القائمة) ويُعيد رابط m3u8.
5. المشغّل يحمّل الرابط الجديد، ويرسل نبضة كل ٢٥ ثانية.
6. عند إغلاق المشغّل تتوقف النبضة، وبعد ٦٠ ثانية بلا نبضة يُنهي المنظّف القناة.

لا شيء من هذا يحتاج تدخّلك.

## الإعدادات في `.env`

```ini
RESTREAM_ENABLED=1
RESTREAM_DIR=/dev/shm/shs_hls    # ذاكرة لا قرص
RESTREAM_PUBLIC=/hls
RESTREAM_MAX_CHANNELS=25         # سقف الحماية من الإرهاق
RESTREAM_IDLE=60                 # ثوانٍ قبل إنهاء قناة مهجورة
RESTREAM_SECRET=...              # يُشتقّ منه اسم مجلد كل قناة
```

`RESTREAM_SECRET` يجعل مسار القناة غير قابل للتخمين. لو استُخدم رقم القناة
مباشرةً لأمكن تصفّح `/hls/1/` و`/hls/2/` والوصول إلى كل شيء بلا اشتراك.

```bash
# حالة القنوات العاملة

# النطاق الفعلي
apt install -y iftop && sudo iftop -i eth0
```

## لماذا `/dev/shm` لا القرص

البثّ الحيّ يكتب ويحذف آلاف الملفات الصغيرة في الساعة. تركها على SSD
يستهلك دورات الكتابة بلا فائدة — المقاطع مؤقّتة بطبعها وتُحذف خلال ثوانٍ.

---

## استكشاف الأعطال

**«الخادم يشغّل أقصى عدد من القنوات»** — بلغت `RESTREAM_MAX_CHANNELS`.
ارفعها إن كان المعالج يحتمل، أو دقّق: قد تكون قنوات مهجورة لم تُنظَّف
(تحقّق أن cron يعمل).

**القناة تبدأ ثم تتوقف** — راجع سجل ffmpeg:
```bash
cat /dev/shm/shs_hls/*/.log
```

**لا صوت رغم الوسيط** — تأكد أنه مفعّل:
```bash
grep RESTREAM_ENABLED /var/www/html/iptv/.env
```

**عمليات ffmpeg تتراكم** — cron لا يعمل:
```bash
systemctl status cron && cat /etc/cron.d/shashety-restream
```
